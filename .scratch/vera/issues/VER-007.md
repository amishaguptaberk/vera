Title: VER-007 — Analyst-approved callback

User value:
Sam authorizes one bounded verification call to the contact on file and gets a transcript plus a structured result that policy can evaluate.

Scope:
- callbacks with attempt, target source, approved question set, transcript lines and structured result stored separately.
- Live Verification Agent on the specialist runner; simulated telephony adapter; outcomes confirmed, contradicted, voicemail, no_answer, incomplete.
- Commands: start_callback, record_callback (service principal), add_callback_note; call detail in Communications; live transcript over the stream.

Non-goals:
- Real telephony.
- Policy rule definitions (VER-008) beyond emitting the result for evaluation.

Acceptance criteria:
- start_callback before identity is verified returns 409 (fixture 29).
- The call target is always the contact on file; a phone number supplied in a message or chat is stored as a claim and never used (fixture 30).
- Each attempt has its own id and record; earlier attempts are never overwritten (US-E02, E03).
- Only `confirmed` satisfies the verification check; every other outcome leaves credit blocked and offers retry (while under two attempts), follow-up or hold.
- A third attempt for the same response is rejected.
- A result cannot be recorded without a transcript; the state reads Transcript unavailable.
- A confirmed result resolves the open conflict with resolved_by set to the call.

Dependencies:
- VER-006

Test-first behavior:
A replay test for the no-answer outcome asserting the callfail step, the preserved attempt and the retry action; then a retry asserting a new attempt id.

Demo proof:
Start the call, watch the transcript append, and show the structured result and the conflict marked resolved.
