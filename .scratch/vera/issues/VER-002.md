Title: VER-002 — Canonical commands and available actions

User value:
Every action the analyst, cardholder, reviewer or card admin can take is one typed, role-checked, versioned command, and the UI can ask exactly which actions are allowed now.

Scope:
- Command gateway with the ten gate stages in plan §6 and the typed error codes in Handoff §3.2.
- CommandSpec registry; `derive_step` as the only writer of state and step; transition rows with all ToSpec §6 fields.
- idempotency_keys table and replay behavior (non-adapter commands in this ticket).
- Demo session: `GET /api/session`, `POST /api/session/role`; seeded users and roles (plan §7).
- `available_actions`, `blocked_actions`, `recovery_actions` in CaseView and `GET /api/cases/{id}/available-actions`; each ActionView carries its server-computed idempotency_key.
- First real commands: `open_case`, `hold_case` (reason and next owner required, gap G3), `resume_case`, `reassign_case`, `link_report`.

Non-goals:
- Adapter-backed commands.
- Investigation, policy, evidence.

Acceptance criteria:
- A command by a role that does not hold it returns 403 role_forbidden and writes no event; verified for every command × role pair in the registry.
- A wrong expected_case_version returns 409 stale_case_version and changes nothing (gap G8).
- Repeating a command with the same key returns status `replayed`, the original result and event ids, and increments attempts only.
- hold_case without reason or next owner returns 422; resume returns the case to the step it would have had, with earlier failures still present (US-J05).
- Every action listed as enabled is accepted by the gateway; every blocked action is rejected with the same blocked_reason.
- Switching role writes no command, no event and leaves case_version unchanged (fixture 37).
- Each accepted command appends exactly one state_transitions row and its declared events, with actor_role set.

Dependencies:
- VER-001

Test-first behavior:
A parametrized test over the role × command table asserting 403 for every non-permitted pair; then a replay test asserting one event after two identical hold_case calls.

Demo proof:
Hold and resume CHG-1042 from curl as Sam; show the 403 when Dana tries; show the replayed response.
