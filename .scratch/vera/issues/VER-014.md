Title: VER-014 — Automations versioning

User value:
An operations admin can change a workflow, specialist or policy through drafts, checks and publish, and running cases stay on the version they started with.

Scope:
- workflow_definitions, workflow_versions (immutable), workflow_drafts, workflow_check_runs; specialist_definitions with draft status; policy_drafts.
- Workflow v3 graph with canonical node `kind` (decision D4); validation rules 1–9 run on edit, save and publish; dry-run of the six scenarios on synthetic adapters.
- Commands through the gateway with role, idempotency and audit (gap G4): create and update workflow draft, run_workflow_checks, publish_workflow_version, discard draft, create and update specialist draft, add_specialist_to_workflow, create_policy_draft, publish_policy_version.
- Read endpoints for workflows, specialists and policies per Handoff §3.2; ops_admin role.

Non-goals:
- Arbitrary code, unrestricted tools or money-moving nodes.
- The builder UI (VER-012-F10).

Acceptance criteria:
- A published workflow or policy version cannot be updated at the database (fixture 22).
- Removing the Policy Controller, a human checkpoint, the evidence recheck, the decision record or the idempotency gate from a money-affecting workflow is rejected when the patch is applied (fixture 40).
- Publish is blocked unless validation passes and checks ran on this exact draft graph with every scenario reaching an end state (fixture 41).
- Publishing leaves CHG-1042 pinned to its start version; new cases use the active version (US-H07).
- A specialist draft with a prohibited tool is rejected; adding a specialist to a workflow creates a draft and never edits the active version (fixture 39).
- The executed graph is built from node kind; changing a node's visual category does not change behavior (fixture 46).
- A policy threshold outside 0–500 is rejected; a draft does not affect existing cases.
- Validation errors name the node and the rule (US-H05).

Dependencies:
- VER-003
- VER-008

Test-first behavior:
A test that patches a draft to remove the Policy Controller and asserts the 422 naming the node and rule.

Demo proof:
Create a draft, run checks, publish v4 and show CHG-1042 still on v3.
