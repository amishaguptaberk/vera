Title: VER-012-F4 — Evidence, activity and run details

User value:
Sam and Dana can open every source record and finding, follow what happened, and inspect technical run details without them crowding the main view.

Scope:
- Evidence tab (comparison table, grouped register, record view), ActivityTable with live append, Run details (metadata, execution safety, trace), run sequence and work entries during investigation.
- Follow docs/frontend-architecture.md for layer rules, state ownership and parity method; the prototype is the visual reference and is not redesigned.

Non-goals:
- Communications.
- Business logic in the client (step, policy, closure, action gating).
- Visual or copy changes from the prototype.

Acceptance criteria:
- Claims, findings and source records are visually distinct (US-C04).
- One activity row is appended per event; nothing else re-renders.
- Run details shows execution mode and model id per step; a replayed step is labeled as such.
- Raw ids, keys and adapter names appear only in Run details.
- Parity passes for the draft-ready and material-change states.

Dependencies:
- VER-012-F3
- VER-003
- VER-004

Test-first behavior:
A test asserting the replayed label renders when execution_mode is replay.

Demo proof:
Start the investigation and watch findings and activity arrive.
