Title: VER-013 — Evaluation suite and CI

User value:
A change that breaks a guarantee — a duplicate credit, a stale approval, an unauthorized action — fails the build with a message that says which case, step and invariant.

Scope:
- Replay harness under evals: scripted commands with assertions on state, step, available actions, evidence status, findings and claims, policy result, approval validity, event sequence, idempotency rows, adapter call counts and recovery action.
- Fixtures 1–24 (ToSpec §15) and 25–46 (Handoff §10.7), added as their tickets land.
- Contract tests: OpenAPI snapshot and enabled-action acceptance.
- GitHub Actions workflow: ruff, format check, mypy, migrations on a Postgres service, unit, integration, contract and replay tests, frontend test and build; all in REPLAY with no provider key.
- CONTRIBUTING.md with the real commands; resettable demo seed.

Non-goals:
- Live-model tests in CI.

Acceptance criteria:
- Each fixture asserts persisted state, not response wording (US-K01).
- A failing fixture names case, workflow version, step and the failed invariant (US-K03).
- Fixtures are deterministic across repeated runs.
- CI fails on invalid transitions, unauthorized actions, duplicate money-like actions, stale approvals, published workflow mutation, missing activity events, unexpected adapter calls, replay mismatch and API drift.
- The harness lands after VER-002 and is green at every later ticket.

Dependencies:
- VER-002

Test-first behavior:
The harness's first fixture: hold and resume, asserting transitions and events.

Demo proof:
Show the CI run green, then a deliberately broken invariant failing with a readable message.
