Title: VER-005 — Follow-up, approval, reply and attachment

User value:
Sam sends one focused question to Priya, Priya answers with a file, and the reply appears in the same case — without anything being sent that Sam did not approve.

Scope:
- Cardholder Follow-up specialist drafts only unresolved questions (on the VER-003 runner).
- communications, communication_drafts, communication_responses; simulated messaging adapter with execution records.
- Commands: update_communication_draft, send_communication, send_reminder, draft_follow_up, submit_cardholder_response, mark_deadline_missed, review_cardholder_response.
- `GET /api/cases/{id}/communications`, `/communications/{item_id}`, `GET /api/requests/{request_id}`, `POST /api/requests/{id}/responses`; deadline_watcher job on the demo clock.
- Attachment validation for size and type (gap G7); send payload carries channel, subject, attachments and case id (gap G5).
- Receipt and Document Reviewer classifies the response as complete, incomplete or conflicting and opens a conflict finding when it contradicts REP-1042.

Non-goals:
- Identity verification and callback.
- Final communication content policy (VER-011).

Acceptance criteria:
- Nothing is delivered until send_communication is run by the analyst; the specialist principal cannot send.
- Double send returns the original delivery result and one communication record, one grouped activity entry (US-D02).
- The cardholder view payload contains no internal ids, policy, specialist names or traces (US-D03).
- A response is a separate immutable record linked to the request; REP-1042 is unchanged.
- An uploaded file is stored as a new evidence version with status Pending review and does not change the policy result (US-C06).
- A missed deadline is recorded once and the case shows overdue with an owner; a reminder is a separate explicit command (US-D04).
- A second follow-up on the same case is rejected.
- A conflicting response creates one open conflict finding and blocks the decision path.

Dependencies:
- VER-004
- VER-003

Test-first behavior:
A test that sends MSG-2201 twice and asserts one delivery; then submits Priya's response with an attachment and asserts the response record, the evidence version and the unchanged policy result.

Demo proof:
Approve and send the draft, switch to the cardholder, reply with the sample file, switch back and show the reply under the original request.
