Title: VER-012-F10 — Automations: workflows, specialists, policies

User value:
An operations admin can inspect and draft workflows, specialists and policies with the same canvas and panels as the prototype.

Scope:
- Workflow builder (canvas ported from the prototype renderer, minimap, step library, inspector, checks panel with three modes), specialists list, detail, permissions drawer, new-specialist drawer, add-to-workflow, appearance; policies view and draft editor.
- Follow docs/frontend-architecture.md for layer rules, state ownership and parity method; the prototype is the visual reference and is not redesigned.

Non-goals:
- Client-side validation or dry-run logic.
- Business logic in the client (step, policy, closure, action gating).
- Visual or copy changes from the prototype.

Acceptance criteria:
- Validation issues and check results come only from the server.
- The canvas is never re-mounted on resize; zoom and selection persist.
- Selecting a trace row selects its node.
- Required controls cannot be removed in the UI and the server rejection is shown if attempted.
- Parity passes for active, draft, checks expanded, compact and collapsed, and the specialist and policy screens.

Dependencies:
- VER-012-F1
- VER-014

Test-first behavior:
A test that a trace-row selection sets the selected node.

Demo proof:
Create a draft, run checks, publish, and show CHG-1042 still pinned.
