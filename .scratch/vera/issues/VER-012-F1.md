Title: VER-012-F1 — Design-system primitives and app shell

User value:
Every screen sits in the real Vera shell: sidebar, top bar, role selector and environment indicator, behaving as in the prototype.

Scope:
- Primitives: Button variants, RefChip, StatusSlot, Tabs, FilterTabs, Table, Drawer, Splitter, Menu, Tooltip, Field, Skeleton, Banner.
- Sidebar (resize 220–320, collapse to 64, mobile drawer), TopBar, RoleSelector, EnvironmentPill; ui-store for panel state.
- Follow docs/frontend-architecture.md for layer rules, state ownership and parity method; the prototype is the visual reference and is not redesigned.

Non-goals:
- Screen content.
- Business logic in the client (step, policy, closure, action gating).
- Visual or copy changes from the prototype.

Acceptance criteria:
- Shell parity states pass at all four widths.
- Sidebar splitter responds to arrows ±16, Shift ±64, Home and End, with the separator roles and values in Handoff §8.2.
- Switching role calls only the session endpoint and never a case command.
- Synthetic environment appears once, in the top bar.
- Status changes in StatusSlot cause no layout shift.

Dependencies:
- VER-012-F0
- VER-002

Test-first behavior:
A component test for the splitter keyboard contract.

Demo proof:
Resize and collapse the sidebar; switch roles.

References: docs/backend-implementation-plan.md, docs/spec/Vera_Handoff.md, docs/spec/Vera_ToSpec.md, docs/spec/Vera_User_Stories.md
