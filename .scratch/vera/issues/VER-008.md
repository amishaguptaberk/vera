Title: VER-008 — Deterministic Policy Controller

User value:
Whether credit is allowed is decided by versioned code that anyone can inspect, and no message, model or chat can talk its way past it.

Scope:
- Pure `evaluate()` in the domain package; policy v1 rules as data with coded predicates (Handoff §7.4 rule groups).
- policy_versions and policy_evaluations; result shape with status, code, label, rules passed and failed, evidence used, snapshot, version.
- evaluate_policy command; policy_reevaluator job on evidence change; policy gate wired into gateway stage 7.
- Policy block in CaseView; `GET /api/policies/{id}` and `/versions/{v}` read-only.

Non-goals:
- Policy drafts and publishing (VER-014).
- Decision packets.

Acceptance criteria:
- [x] The same snapshot and policy version always produce the same result.
- [x] Missing receipt above the threshold yields needs_evidence; an open conflict yields blocked; verified and complete evidence yields eligible; an authorized charge yields ineligible.
- [x] A finding or message asserting that policy is satisfied does not change the result (fixture 21).
- [x] Every evaluation is persisted with the evidence ids it used.
- [x] An evidence change triggers re-evaluation and a `policy.evaluated` event.
- [x] The evaluator imports no model, network or database code.

Dependencies:
- VER-004

Test-first behavior:
A table-driven unit test mapping evidence snapshots to expected status, code and failed rules.

Demo proof:
Show the policy result for CHG-1042 before the receipt, after the reply and after the confirmed call.
