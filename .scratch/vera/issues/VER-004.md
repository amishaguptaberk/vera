Title: VER-004 — Evidence provenance, snapshots and conflicts

User value:
A reviewer can trust that every finding points at a real, versioned source record, and that changed evidence visibly invalidates what depended on it.

Scope:
- Tables and services for evidence_records, evidence_versions, findings, finding_links, attachments; statuses Supporting / Missing / Conflicting / Superseded / Pending review / Not relevant.
- Seed source records: CHG-1042, PO-219, DLV-882, REP-1042, PRF-4418, related CHG-1051 and CHG-1048.
- Snapshot hash over current evidence versions and policy-material fields (plan §10); stored on the case.
- Material-change pipeline: append version, recompute hash, mark only affected checks and approvals stale, emit `evidence.version_added` and `approval.stale`.
- Structured conflict findings with status open / resolved (resolved_by) / accepted_unresolved.
- `GET /api/cases/{id}/evidence` and `/evidence/{record_id}`; `link_evidence`, `record_claim`, `record_finding` as service-principal commands; `/api/demo/material-change`.

Non-goals:
- Model-backed extraction (VER-003).
- Policy rules (VER-008).
- Decision packets and approvals beyond the stale-marking hook.

Acceptance criteria:
- [x] Replacing a document creates a new version; the old one is retained and marked superseded (US-C07).
- [x] A finding without at least one existing source-record link is rejected.
- [x] Missing evidence and conflicting evidence are distinct statuses in the register (US-C02).
- [x] A material change to DLV-882 changes the snapshot hash; a non-material change does not.
- [x] Only checks mapped to the changed evidence kind are marked stale; unrelated checks keep their status (US-F05).
- [x] evidence_versions rows cannot be updated or deleted.
- [x] A specialist principal cannot mutate a source record (fixture 19).

Dependencies:
- VER-002

Test-first behavior:
A test that records DLV-882 v2 with a changed received quantity and asserts: new version row, v1 superseded, hash changed, only the purchase-records check stale.

Demo proof:
Call the material-change demo endpoint and show the register and snapshot hash before and after.
